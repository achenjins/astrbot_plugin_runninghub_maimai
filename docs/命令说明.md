# 命令说明

所有命令都以 `/wf` 开头（`/wf 保存提示词` 这种中间有空格的，是 `wf` 下的子命令）。

- `<参数>` 必填，`[参数]` 可选。
- 参数之间用空格分隔，中英文冒号、逗号也行，比如 `/wf运行：文生图 一只猫`。

---

## 运行与中断

### /wf运行 <工作流名> [描述]

按当前配置运行一个工作流。带描述时，工作流开启了扩写会先扩写再提交。

```text
/wf运行 文生图 原神刻晴
```

需要参考图或其他文件时，机器人会引导你逐个上传；标记为可选的输入可以回「跳过剩余」。可编辑参数会列出来让你改，回「不变」就用默认值。

### /wf中断

- 还在收集输入的阶段：直接结束这次操作。
- 已经提交到平台：回复编号取消运行中的任务。

---

## 识别工作流

| 命令 | 作用 |
| --- | --- |
| `/wf工作流` | 列出已配置的全部工作流 |
| `/wf国外工作流 <工作流ID> [名称]` | 识别 runninghub.ai 上的工作流 |
| `/wf国内工作流 <工作流ID> [名称]` | 识别 runninghub.cn 上的工作流 |
| `/wf详细国外工作流 <工作流ID> [名称]` | 用 LLM 详细识别 runninghub.ai 工作流 |
| `/wf详细国内工作流 <工作流ID> [名称]` | 用 LLM 详细识别 runninghub.cn 工作流 |

- 普通识别只取最常用的输入节点（提示词、图片、音频、视频、分辨率、长宽比），大多数场景够用。
- 详细识别会把步数、采样器、CFG、种子、lora 强度等参数也列出来，变成每次运行前可以修改的配置，更全但更慢，也可能识别出用不到的节点。
- 识别成功后建议在 Pages 或配置页核对一遍，删掉用不到的节点。

## 提示词

| 命令 | 作用 |
| --- | --- |
| `/wf 保存提示词` | 从最近 5 条扩写提示词里选一条持久保存 |
| `/wf 提示词重跑` | 复用最近一次扩写提示词，重新收集文件和参数后运行 |
| `/wf 提示词` | 列出已保存的提示词 |
| `/wf 上传提示词` | 上传一条可以在「提示词」列表里直接运行的提示词 |
| `/wf 上传提示词模板` | 上传 `.md` / `.txt` 扩写模板 |

用法：

1. `/wf 保存提示词`：回复编号，再发一句保存描述。
2. `/wf 提示词`：回复数字运行对应提示词；回复 `删除1` 删除第 1 条；回复 `取消` 退出。
3. `/wf 提示词重跑`：直接复用最近一条扩写提示词，不再调用 LLM。
4. `/wf 上传提示词`：先选择对应工作流，再发 `.md` / `.txt` 文件；文件名作为提示词描述。
5. `/wf 上传提示词模板`：发送 `.md` / `.txt` 文件，保存到持久化的模板目录，可在工作流配置页选择。

两种上传都会自动识别 UTF-8、UTF-16、GB18030/GBK、Big5 等编码，统一转成 UTF-8。

提示词按平台和用户隔离。每次成功提交后保留最近 5 条实际使用的扩写提示词；复用提示词时直接用扩写结果，不会重复调用 LLM。

## 任务管理

### /wf状态 [任务ID]

查看本会话的任务，并恢复对排队中、已有平台编号任务的后台查询，不会重新提交。不带参数时列出最近的任务。

### /wf补发 [任务ID或最新] [结果序号或全部]

把已经生成好的结果再发一次，不重新生成、不再扣费。

- `/wf补发 列表`：列出本会话近期可补发的结果。
- 不带参数：补发最新任务里还没成功发出的项。
- `/wf补发 最新` 或 `/wf补发 <任务ID>`：指定任务。
- 指定结果：`/wf补发 <任务ID> 2`，多项用逗号：`/wf补发 <任务ID> 1,3`；`全部` 发送该任务的所有结果。

补发依赖平台结果链接仍在有效期内；链接过期后无法补发。

### /wf核对 <任务ID> <平台任务ID|未创建>

仅插件管理员可用，只在任务处于「提交未确认」状态时使用。

提交任务要扣钱。如果提交时网络中断或平台没回响应，插件无法确认任务到底建没建，会冻结这个任务的运行名额，也不会自动重提——万一任务已经在平台上创建了，重提就是扣两次钱。

管理员先到 RunningHub 后台任务列表人工确认，再按实际情况发送命令：

| RunningHub 后台 | 发送的命令 | 插件的动作 |
| --- | --- | --- |
| 找到了刚提交的任务 | `/wf核对 <任务ID> <平台任务ID>` | 绑定平台编号，继续跟踪这个任务并回传结果 |
| 确认没有新任务 | `/wf核对 <任务ID> 未创建` | 标记为已取消，释放冻结的名额 |

- 任务 ID 发 `/wf状态` 就能查到；「提交未确认」时状态回复里会直接提示该用哪条核对命令。
- 平台任务 ID 不能和其他任务重复绑定。
- 核对只做补登或销账，不会重新生成，也不再扣费。

---

## 任务状态含义

| 状态 | 含义 |
| --- | --- |
| 排队中 | 运行名额已满，任务在等待 |
| 正在提交 | 正在向平台发起付费提交 |
| 提交未确认 | 提交后没有得到平台确认，名额冻结，等待管理员核对 |
| 生成中 | 已提交成功，等待平台出结果 |
| 查询已暂停 | 查询暂时失败，稍后会继续跟踪，不代表生成失败 |
| 需要处理 | 查询或取消被平台明确拒绝，需要修复配置后恢复 |
| 生成成功 / 生成失败 / 已取消 | 任务结束的三种状态 |

结果的发送状态单独记录：全部发出、部分发出、发送失败、发送情况不明。发送情况不明时先查看聊天记录，再决定是否补发，避免重复刷屏。

## 数据存放位置

插件运行产生的数据都在 AstrBot 数据目录的 `data/plugin_data/<插件目录>/` 下，不会写进插件源码目录，更新插件不会丢：

| 路径 | 内容 |
| --- | --- |
| `prompt/` | 扩写模板文件 |
| `prompt_library.json` | 最近提示词和已保存提示词 |
| `task_journal.json` | 任务记录与结果发送状态 |
| `task_inputs/` | 排队任务单独保存的输入文件 |
| `chat_media/` | 聊天中使用的参考图片 |
| `image_memory/` | 最近图片记忆的原图与简介 |
